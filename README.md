## 🎯 О проекте

**Agronomist** — это enterprise-решение для современных фермерских хозяйств и агрохолдингов. Платформа собирает данные с полей, складов и техники, обрабатывает их с помощью алгоритмов (включая Закон Либиха и ГОСТы) и предоставляет удобный интерфейс для принятия управленческих решений.

---

## 🚀 Основной функционал системы

### 🌍 1. Управление Полями (Fields & Weather)
* **Точное земледелие:** Визуализация полей на интерактивных картах (Leaflet) с четкими геозонами.
* **Кадастровый реестр:** Учет площади, севооборота, типа почвы и истории посевов.
* **Умная Агропогода:** Интеграция с Open-Meteo. Гиперлокальный прогноз температуры, осадков, влажности и скорости ветра для координат каждого конкретного поля.
* **Система алертов:** Автоматический расчет теплового стресса (Heat Stress) для различных культур и предупреждения о засухе.

### 🚜 2. Мониторинг Техники и ГСМ (Machinery)
* **Автопарк:** Ведение базы тракторов, комбайнов, сеялок и прицепного оборудования.
* **Топливный контроль:** Детальный мониторинг уровня ГСМ. Автоматический расчет норм расхода и выявление подозрительных сливов или перерасхода топлива.
* **Наряды и Путевые листы:** Электронные наряды на выполнение работ. Учет обработанных гектаров, моточасов и превышения скоростного режима при выполнении операций (например, при посеве).
* **Журнал ТО:** Автоматические уведомления о необходимости технического обслуживания при достижении заданных моточасов.

### 🌱 3. Прогнозирование Урожайности (Yield)
* **Агрохимический анализ:** Учет состояния почвы (pH, гумус, азот, фосфор, калий).
* **Модель Либиха:** Математическое моделирование потенциальной урожайности на основе «Закона минимума Либиха».
* **Поиск узких мест:** Алгоритмы автоматически находят лимитирующий фактор (элемент, которого не хватает больше всего), не дающий повысить урожайность.

### 🧮 4. Агрокалькулятор (Calculator)
* **Баланс NPK:** Умный расчет дефицита питательных веществ (азот, фосфор, калий) для достижения плановых показателей.
* **Блокировка макроэлементов:** Эвристическая модель, определяющая блокировку фосфора или азота из-за слишком высокой/низкой кислотности (pH) почвы.
* **Норма высева:** Быстрый подсчет количества посевного материала (в кг/га и млн. шт./га) с учетом всхожести и массы 1000 семян.

### 🏭 5. Склад и Качество Зерна (Warehouse)
* **Силосы и Элеваторы:** Визуальный контроль вместимости и загруженности складов.
* **Лаборатория качества:** Учет влажности, сорности, протеина, клейковины и числа падения для каждой партии.
* **Авто-ГОСТ:** Система автоматически присваивает класс зерну (с 1 по 6 класс) на основе введенных лабораторных анализов.
* **Мониторинг хранения:** Отслеживание температуры в бункерах с мгновенными алертами о риске самовозгорания или порчи урожая.

### 🔒 6. Безопасность и Доступ (Auth)
* **Защита JWT:** Ролевая модель и авторизация через Access и Refresh токены.
* **Redis Сессии:** Безопасное хранение, отзыв и ротация refresh-токенов через in-memory БД.
* **OAuth 2.0:** Бесшовная авторизация через Google аккаунты.

### 📡 7. Офлайн-режим (Offline)
* **PWA & LocalStorage:** Возможность работать в поле без связи.
* **Синхронизация:** Сбор данных локально с последующей пакетной отправкой (Sync) при появлении интернета.

## 🛠 Технологический стек и Архитектура

Проект построен с использованием современной микросервисной архитектуры и контейнеризации.

| Уровень | Технологии | Назначение |
|---|---|---|
| **Frontend** | React, Vite, Tailwind, Leaflet, Recharts | SPA-приложение, интерактивный дашборд, карты, графики. |
| **Backend** | Python 3.10, FastAPI | Высокопроизводительный асинхронный API-сервер. |
| **База Данных** | PostgreSQL 15, SQLAlchemy, Alembic | Реляционное хранение данных, ORM и версионирование схемы (миграции). |
| **Кэш / Сессии** | Redis | Rate-limiting (SlowAPI), хранение сессий, ротация токенов. |
| **Инфраструктура**| Docker, Docker Compose, GitHub Actions | Изоляция окружений, оркестрация, автоматический CI/CD. |

## 📦 Установка и Развертывание (Deployment)

### Локальный запуск (Docker)

Проект полностью контейнеризирован, что делает его запуск максимально простым.

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/StanislavRudyk/practice.git
   cd practice
   ```

2. **Настройте переменные окружения:**
   Создайте файл `.env` в корневой папке на основе примера:
   ```env
   POSTGRES_USER=admin123
   POSTGRES_PASSWORD=admin123
   POSTGRES_HOST=db_postgres
   POSTGRES_DB=admin123
   REDIS_HOST=db_redis
   REDIS_PORT=6379
   REDIS_PASSWORD=redis123
   SECRET_KEY=your_super_secret_key_here
   ACCESS_TOKEN_EXPIRE_MINUTES=30
   REFRESH_TOKEN_EXPIRE_DAYS=7
   ALLOWED_ORIGINS=http://localhost:3000
   LOGIN_RATE_LIMIT=5/minute
   ```

3. **Запустите проект:**
   ```bash
   docker-compose up -d --build
   ```

> 💡 **Автоматизация БД:** При старте контейнера, FastAPI автоматически создает все необходимые таблицы через `Base.metadata.create_all`. Дополнительно применять миграции Alembic при локальном развертывании не нужно.

### API Документация
После запуска бэкенда, интерактивная Swagger-документация доступна по адресу:
👉 [http://localhost:8000/api/docs](http://localhost:8000/api/docs)

## ⚙️ CI/CD (GitHub Actions)

В проекте настроен автоматический деплой (Continuous Deployment). 
Файл конфигурации: `.github/workflows/deploy.yml`

**Пайплайн деплоя:**
1. Триггер срабатывает при пуше (Push) в ветку `main`.
2. Поднимается виртуальная машина (runner) `ubuntu-latest`.
3. Устанавливается Node.js (v20).
4. Происходит сборка frontend-части: `npm install && npm run build`.
5. Собранные статические файлы копируются на production-сервер по SSH (через `appleboy/scp-action`).
6. Бэкенд-файлы копируются на сервер.
7. На сервере активируется виртуальное окружение, обновляются зависимости `pip install -r requirements.txt`.
8. Перезапускается процесс `uvicorn`.
